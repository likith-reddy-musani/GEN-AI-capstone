=== SECTION 1: THE XYZ BULLET FORMULA (DEEP DIVE) ===
The gold standard for technical resume bullet points is Google's structural standard:
  "Accomplished [X] as measured by [Y] by doing [Z]"

Component Breakdown:
  [X] = Core Achievement & Outcome:
        State the tangible outcome or problem resolved, not the everyday chore.
  [Y] = Quantified Impact & Delta:
        Provide concrete before/after metrics, percentage deltas, throughput, operational savings, or scale.
  [Z] = Implementation Mechanics & Stack:
        Specify the exact technologies, architectural patterns, data structures, and engineering methods leveraged.

Advanced Bullet Construction Patterns:
  1. Performance & Latency Pattern:
     [Action Verb] [System Component] to achieve [Y Metric Improvement] by implementing [Z Technical Architecture].
  2. Cost & Efficiency Pattern:
     Reduced [Cost/Resource Overhead] by [Y%] across [Scale Indicator] through [Z Optimization Technique].
  3. Reliability & Availability Pattern:
     Increased [Uptime/Reliability SLI] from [Base] to [Target] by designing [Z Fault-Tolerant System].

Weak vs. Strong Engineering Rewrites:
  - Backend Engineering:
    WEAK:   "Worked on backend APIs and fixed performance bugs."
    STRONG: "Reduced P99 API response latency by 42% (from 320ms to 185ms) for a peak load of 15K req/sec by implementing Redis multi-tier caching, connection pooling, and composite database indexing in PostgreSQL."

  - Cloud & DevOps Infrastructure:
    WEAK:   "Helped manage AWS infrastructure and Docker deployments."
    STRONG: "Eliminated deployment downtime and cut pipeline duration by 58% (from 24m to 10m) by architecting a declarative GitOps CI/CD pipeline using GitHub Actions, Helm, and ArgoCD on an AWS EKS cluster."

  - AI / ML Engineering:
    WEAK:   "Built a machine learning model to categorize text."
    STRONG: "Achieved a 93.8% F1-score and cut inference latency by 65% on a customer intent classifier by fine-tuning an open-source Llama model via QLoRA, quantizing weights to 4-bit AWQ, and serving via vLLM."

  - Data Analytics & Analytics Engineering:
    WEAK:   "Created dashboards and wrote SQL queries for stakeholders."
    STRONG: "Identified $180K in annual subscription leakages by modeling customer churn cohorts across 250K user accounts using dbt, SQL window functions, and interactive Tableau dashboards with automated alert thresholds."

  - System Reliability & Security:
    WEAK:   "Handled security checks and reduced software errors."
    STRONG: "Mitigated 100% of high-severity CVE vulnerabilities across 45 microservices by integrating automated Trivy container scans and Snyk static code analysis into the pull-request review gate."

=== SECTION 2: ATS FORMATTING & TECHNICAL INGESTION RULES ===
Parser Compatibility Criteria:
  - Layout Architecture:
    Use a strict single-column layout. Multi-column formatting breaks the top-to-bottom parser reading order.
  - Restricted Visual Elements:
    Do not use tables, text boxes, images, icons, embedded graphics, borders, or text placed inside header/footer bands.
  - Section Header Semantics:
    Use standard, unadorned header labels: "Technical Skills", "Work Experience", "Education", "Projects", "Certifications".
  - Font Standards:
    Stick to clean system fonts: Arial, Calibri, Helvetica, or Times New Roman (10-11pt for body, 13-15pt for section headings).
  - Document Format:
    Submit as text-layer searchable PDF. Verify text can be highlighted and copied cleanly without OCR artifacts.
  - Page Budgeting:
    Strictly 1 page for individuals with 0 to 4 years of experience. Maximum 2 pages for senior or lead staff engineers.
  - Hyperlink Styling:
    Display clean URLs or anchor text without full URL clutter (e.g., "github.com/username", "linkedin.com/in/username").
  - Technical Acronyms:
    Write the standard acronym alongside full terminology on first occurrence: "Role-Based Access Control (RBAC)".
  - Grammatical Voice:
    Zero first-person pronouns (I, me, my, we). Begin every bullet directly with an imperative past-tense action verb.

=== SECTION 5: QUANTIFICATION STRATEGIES & METRIC FORMULAS ===
Every project or experience bullet must contain at least one verifiable metric:
  1. Performance & Latency:
     "Reduced P95/P99 latency by [X]%", "Lowered TTFT (Time To First Token) by [X]ms", "Boosted throughput by [X]x"
  2. Infrastructure Scale & Volume:
     "Processed [X] million daily events", "Indexed [X] GB of unstructured documents", "Managed [X] EC2 nodes across [Y] VPCs"
  3. Reliability, Errors & Quality:
     "Decreased production defect rate by [X]%", "Maintained 99.95% system uptime", "Achieved [X]% code coverage via Pytest"
  4. Cost & Resource Optimization:
     "Lowered cloud compute spend by $[X]/month", "Decreased memory footprint by [X]MB", "Reclaimed [X]% idle GPU memory"
  5. Developer Velocity & CI/CD Efficiency:
     "Reduced build and deployment duration from [A] minutes to [B] minutes", "Automated [X] manual verification steps"
  6. Contextual Proxy Scoping (When numerical business data is missing):
     "Built for a cross-functional group of [X] engineers, supporting [Y] internal endpoints over a [Z]-month release cycle"

=== SECTION 6: COMMON RED FLAGS & REMEDIATION CHECKLIST ===
  [ ] Flag: Objective Statements
      Fix: Replace generic objective statements with a 3-line Technical Summary detailing core competencies, stack, and domain.
  [ ] Flag: Passive Responsibilities
      Fix: Transform "Responsible for maintaining servers" into "Automated host configuration and patching for 25+ Linux servers".
  [ ] Flag: Vague Technology References
      Fix: Replace "Used machine learning and modern databases" with "Trained XGBoost models and stored vectors in ChromaDB".
  [ ] Flag: Missing Hyperlinks & Evidence
      Fix: Include verified clickable links to GitHub source repositories, live project URLs, and production demos.
  [ ] Flag: Irrelevant Skill Padding
      Fix: Eliminate generic workplace entries like "Team Player", "Fast Learner", "Microsoft Word", and "Agile Methodology".
  [ ] Flag: Inconsistent Verb Tense
      Fix: Enforce past-tense verbs for completed projects and previous roles; reserve present tense strictly for active roles.
  [ ] Flag: Unexplained Chronological Gaps
      Fix: Account for structural timeline gaps with explicit educational terms, contract sprints, or open-source contribution tracks.
  [ ] Flag: Outdated Coursework Clutter
      Fix: Deprecate intro-level CS coursework (e.g., Intro to Computers); feature high-value electives (Distributed Systems, Cloud Architecture).

=== SECTION 7: STEP-BY-STEP AUDIT & GRADING SCORECARD ===
When evaluating or scoring a technical resume, grade across these core benchmarks (Target: 90+/100):
  1. Structural Formatting & ATS Rigor (20 Points):
     - Single-column text layout without tables, columns, or text boxes (10 pts)
     - Standard header syntax, consistent margin spacing, valid PDF text layer (10 pts)
  2. Quantification Density (30 Points):
     - Minimum of one quantifiable metric per bullet across all work entries (15 pts)
     - Explicit measurement deltas indicating before-and-after baseline improvements (15 pts)
  3. Technical Stack Transparency (25 Points):
     - Concrete tool, framework, and language attribution declared directly inside every project bullet (15 pts)
     - Dedicated, categorized skills inventory matching the target job description (10 pts)
  4. Action Verb Authority & Grammatical Rigor (15 Points):
     - Every single bullet point begins with a powerful, distinct past-tense technical action verb (10 pts)
     - Complete elimination of passive voice and first-person personal pronouns (5 pts)
  5. Relevance & Information Hierarchy (10 Points):
     - Reverse chronological layout with projects and experience prioritized above education for experienced roles (5 pts)
     - Clean contact block with location, email, phone, LinkedIn, and active GitHub URL (5 pts)
